# ระบบหน้าตาของส่วนใบเบิก (Finance)

ใช้กับทุกหน้าที่ทำใหม่ในขั้น 4–7 ของ `docs/specs/finance-refactor-plan.md` — แบบ **A เรียบร้อย** (เจ้าของเลือก 2026-09-30):
พื้นขาว/zinc การ์ดมุมโค้ง 12px (`rounded-xl`) ขอบ zinc-200 (มืด: zinc-800) ปุ่มหลักสีเขียว emerald

ตัวอย่างที่ทำตามกติกานี้แล้ว: คิวใบเบิก `queue-*.tsx`, `status-badge.tsx`, `send-back-dialog.tsx`
ชุดตรวจ `scripts/finance-queue-view.check.ts` ตรวจกติกาข้อ "ขนาด" "ปุ่ม" และ "ช่องกรอก" ของไฟล์เหล่านี้ทุกครั้งที่รัน

## หนึ่งความหมาย หนึ่งสี

| สี | ความหมาย |
|---|---|
| emerald | ครบ / ทำต่อได้ / ปุ่มหลัก / อนุมัติแล้ว |
| amber | รอใครบางคน / ต้องดู (รออนุมัติ, รอผู้เบิกเคลียร์, ส่งกลับให้แก้) |
| red | ขาด / ผิดพลาด / ปฏิเสธ / ล็อกการจ่าย |
| sky | ใบกำกับภาษี |
| violet | จ่ายสิ้นเดือน |
| teal | จ่ายแล้ว |
| cyan | คืนเงินบริษัทแล้ว |
| zinc | กลาง (แบบร่าง, ยกเลิก, ไอคอน, ข้อความรอง) |

- **สีของสถานะมีที่ `StatusBadge` ที่เดียว** — ห้ามใช้ `getClaimStatusColor` หรือใส่สีสถานะเองในหน้าที่ทำใหม่ ไอคอนสถานะในแถวเป็นสีกลาง (zinc)
- **แหล่งเงินไม่มีสี** — แสดงเป็นไอคอน + ข้อความเท่านั้น (`User` = เงินส่วนตัว, `Building2` = เงินบริษัท) ห้ามใช้ `getFundingSourceColor`
  เหตุผล: ของเดิมให้เงินส่วนตัวเป็น amber (ชนกับ "รออนุมัติ") และเงินบริษัทเป็น sky (ชนกับ "รอใบกำกับภาษี") —
  เงินส่วนตัว/เงินบริษัทจึงต้องไม่ใช้ amber หรือ sky ซ้ำกับสถานะ
- ไม่พึ่งสีอย่างเดียว: ป้ายทุกอันมีไอคอนและข้อความ

## ป้ายสถานะ (`StatusBadge`) — 10 สถานะ

ตัวหนังสือเข้มบนพื้นอ่อน ผ่านเกณฑ์ AA: สว่าง `text-{สี}-800 bg-{สี}-100` · มืด `text-{สี}-200 bg-{สี}-950/60` ·
`text-xs font-semibold rounded-full px-2.5 py-1` + ไอคอน lucide

| สถานะ | ชื่อ | สี | ไอคอน |
|---|---|---|---|
| `draft` | แบบร่าง | zinc | `FileEdit` |
| `pending` | รออนุมัติ | amber | `Clock` |
| `approved` | อนุมัติแล้ว | emerald | `CheckCircle2` |
| `waiting_tax_invoice` | รอใบกำกับภาษี | sky | `Receipt` |
| `pending_month_end` | รอจ่ายสิ้นเดือน | violet | `CalendarClock` |
| `paid` | ชำระเงินแล้ว | teal | `Banknote` |
| `refund_confirmed` | คืนเงินบริษัทแล้ว | cyan | `RefreshCw` |
| `rejected` | ปฏิเสธ | red | `XCircle` |
| `cancelled` | ยกเลิกแล้ว | zinc | `Ban` |
| `awaiting_payment` | รอชำระเงิน (เก่า) | emerald | `CheckCircle2` |

## ป้ายอื่น (ไม่ใช่สถานะ)

ใช้ `Badge variant="outline"` + คู่สีเดียวกับป้ายสถานะ (`-100/-800`, มืด `-950/60 / -200`) + ไอคอน

| ป้าย | สี | ไอคอน | ที่มา |
|---|---|---|---|
| ขาดใบเสร็จ | red | `AlertCircle` | `paymentLock().missing` มี "ใบเสร็จ" |
| ต้องมีใบกำกับ | sky | `FileText` | `paymentLock().missing` มี "ใบกำกับภาษี" |
| เอกสารครบ | emerald | `CheckCircle2` | ไม่ติดล็อกการจ่าย |
| รอผู้เบิกเคลียร์ | amber | `Hourglass` | `advanceState() === 'unsettled'` |
| รอยืนยันเงินคืน | amber | `RefreshCw` | `advanceState() === 'refund_pending'` |
| เข้าแฟ้มแล้ว | กลาง (outline) | `FolderCheck` | `filedState() === 'filed'` |
| ไฟล์แนบเปลี่ยนหลังเข้าแฟ้ม | amber | `AlertCircle` | `filedState() === 'changed'` |

ข้อความล็อกการจ่าย ("เอกสารไม่ครบ …") มาจาก `paymentLock().message` ใน `claim-rules.ts` ที่เดียว — หน้าจอแสดงข้อความนั้นตรงๆ

## ปุ่ม — 4 ระดับ

ใช้ `Button` ของ shadcn เท่านั้น (ไม่มี `<button>` ดิบ)

| ระดับ | shadcn | ใช้เมื่อ |
|---|---|---|
| หลัก | `variant="default"` + คลาส `PRIMARY_BUTTON` (`queue-row.tsx`: `bg-emerald-700 text-white hover:bg-emerald-800`) | การกระทำหลักของพื้นที่นั้น (อนุมัติ, จ่าย, ยืนยันเงินคืน, สร้างใบเบิก) — ไม่เกินหนึ่งปุ่มต่อแถว/ต่อแผง |
| รอง | `variant="outline"` | ทางเลือกที่ใช้บ่อย (ส่งกลับให้แก้, ขอใบกำกับภาษี, ย้ายไปจ่ายสิ้นเดือน, ก่อนหน้า/ถัดไป) |
| ข้อความ | `variant="ghost"` | ลิงก์/เครื่องมือรอง (เปิดใบ, ปฏิเสธในแผงข้าง, ล้างที่เลือก, ใบที่ซ่อนไว้) |
| อันตราย | `variant="destructive"` | การกระทำที่ย้อนไม่ได้ — ยืนยันใน dialog (`useConfirm` variant `destructive`) ก่อนเสมอ |

- primary ของธีม shadcn เป็นสีดำ — ส่วนใบเบิกใส่ `PRIMARY_BUTTON` ทับ (สีขาวบน emerald-700 = 5.5:1)
- ปุ่มที่กดไม่ได้เพราะกติกา (เช่น ล็อกการจ่าย) ต้องมี `title` **และ** ข้อความเหตุผลใต้ปุ่ม (ปุ่มที่ปิดอยู่ไม่แสดง tooltip)
- ปุ่มที่กำลังทำงานหมุน (`Loader2 animate-spin`) และปุ่มอื่นของพื้นที่เดียวกันปิดชั่วคราว
- ปุ่มไอคอนอย่างเดียวต้องมี `aria-label`

## ขนาด

| เรื่อง | กติกา |
|---|---|
| ตัวหนังสือ | ไม่เล็กกว่า 12px (`text-xs`) — ห้าม `text-[9px]` `text-[10px]` `text-[11px]` |
| ช่องกรอกบนมือถือ | 16px (`Input` ของ shadcn เป็น `text-base md:text-sm` อยู่แล้ว — iOS ไม่ซูม) |
| จุดแตะ | ไม่เล็กกว่า 40px: ปุ่ม `size="lg"` (h-10) หรือ `min-h-10` · `SelectTrigger`/`Input` ใส่ `min-h-10`/`h-10` · ช่องติ๊ก 16–20px อยู่ใน `<label>` ขนาด 40×40 |
| จอแคบ | ใช้ได้ที่ 360px โดยหน้าไม่เลื่อนแนวนอน — แถวที่ปุ่มเยอะให้ขึ้นบรรทัดใหม่ แถบปุ่มที่ยาวเลื่อนแนวนอนในแถบเอง |

## ช่องกรอก

- ทุกช่อง (`Input`, `Textarea`, `SelectTrigger`, `Checkbox`) มี `aria-label` หรือ `<Label htmlFor>` ที่ผูกกับ `id` ของช่อง
- ข้อผิดพลาดขึ้นใต้ช่อง/ใต้ปุ่มที่กด (`role="alert"`) + toast ภาษาไทยทุกผลลัพธ์ (sonner)

## โหมดมืด

ทุกสีมีคู่ `dark:` — พื้นการ์ด `dark:bg-zinc-900` ขอบ `dark:border-zinc-800` ข้อความรอง `dark:text-zinc-400` ป้ายใช้คู่ `-950/60 / -200`
