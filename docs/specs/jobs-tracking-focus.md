# Spec: โฟกัสงาน + ตำแหน่งที่ต้องการ + ลดเลน (ไทม์ไลน์ /jobs/tracking)

Status: ready-for-agent · ต่อจาก `docs/specs/jobs-tracking-timeline.md`
Glossary: `CONTEXT.md` (โฟกัสงาน, ตัวเลือก, ภาระงาน, ตำแหน่งที่ต้องการ, จัดคนครบ, ความพร้อม)

## Problem Statement

ไทม์ไลน์แสดงเลนคนทุกคนที่อนุมัติแล้วเรียงตามแผนก วันที่ยังไม่จัดใครเลยจึงเป็นเลนว่างยาวเป็นสิบแถว และงานที่ยังไม่จัดคนไม่มีจุดอ้างอิงให้เทียบว่า "ใครว่างช่วงนั้น" ปุ่ม "ซ่อนคนว่าง" ยิ่งซ่อนคนที่อยากเลือก ระบบยังไม่รู้ว่างานหนึ่งต้องใช้ตำแหน่งอะไรกี่คน จึงบอกได้แค่ "มีคนแล้ว/ยังไม่มี" ไม่ใช่ "ยังขาดใคร"

## Solution

1. **ตำแหน่งที่ต้องการ** ต่องาน (ตำแหน่ง × จำนวน) กำหนดได้จาก CRM, หัวโฟกัสงาน และหน้าต่างจัดคน — ความพร้อมเปลี่ยนจาก "มีคน ≥1" เป็น "จัดคนครบ" และป้ายบอกตรงๆ ว่าขาดตำแหน่งไหนกี่คน
2. **โฟกัสงาน**: คลิกงานในไทม์ไลน์ → ช่วงเวลางานพาดทุกเลน เลนคนจัดใหม่เป็น "ตัวเลือก" (ว่าง → ต่อคิว → เช็คเวลาไม่ได้ ภาระงานน้อยก่อน) กับ "ไม่ว่าง" (ชน ยุบไว้) คลิกเลนตัวเลือกเพื่อจัดทันที
3. **ลดเลน**: ยุบกลุ่มแผนกเป็นค่าเริ่มต้น (หัวกลุ่มบอกจำนวนคน/ว่าง), ชิปกรองแผนก, ตัวเลขภาระงานข้างชื่อ, ถอน "ซ่อนคนว่าง"

## User Stories

1. As ฝ่ายประสานงาน, I want กำหนด "ตำแหน่งที่ต้องการ" ของงาน (เช่น ช่างกล้อง 1, ผู้ช่วย 2) จากการ์ดข้อมูลอีเวนต์ใน CRM, so that ระบบรู้ว่างานนี้ต้องใช้ใครบ้าง
2. As ฝ่ายประสานงาน, I want แก้ตำแหน่งที่ต้องการได้จากหัวโฟกัสงานและหน้าต่างจัดคนด้วย, so that ปรับตอนวางแผนได้โดยไม่กลับไป CRM
3. As ฝ่ายประสานงาน, I want ป้ายความพร้อมบอก "ขาด: จัดคน (ผู้ช่วย 1)" เมื่อกำหนดตำแหน่งแล้วแต่คนยังไม่ครบ, so that รู้ว่าต้องหาใครเพิ่ม
4. As ฝ่ายประสานงาน, I want งานที่ยังไม่กำหนดตำแหน่งใช้กติกาเดิม (มีคน ≥1 = จัดคนแล้ว) และมีคำเตือนเบาๆ ว่ายังไม่กำหนด, so that งานเก่าไม่กลายเป็น "ไม่พร้อม" ทั้งกระดานในวันที่อัปเดต
5. As ฝ่ายประสานงาน, I want คนเกินหรือตำแหน่งอื่นที่เพิ่มเข้ามาไม่ทำให้งาน "ไม่ครบ", so that จัดคนเสริมได้ตามหน้างานจริง
6. As ฝ่ายประสานงาน, I want คลิกแถบงานในเลน "งาน" แล้วไทม์ไลน์เข้าโฟกัสงานนั้น, so that เริ่มเทียบคนจากงานที่จะจัด
7. As ฝ่ายประสานงาน, I want หัวโฟกัสบอก "ลูกค้า · เวลา · มีแล้ว: … · ขาด: …" และปุ่มออก, so that รู้สถานะงานตลอดเวลาที่จัด
8. As ฝ่ายประสานงาน, I want ช่วงเวลาของงานโฟกัสพาดเป็นแถบโปร่งลงทุกเลน, so that เห็นทันทีว่าใครมีงานทับช่วงนั้น
9. As ฝ่ายประสานงาน, I want เลนคนในโฟกัสแบ่งเป็น "ตัวเลือก" (เรียง ว่าง → ต่อคิว → เช็คเวลาไม่ได้ แล้วภาระงานน้อยก่อน) และ "ไม่ว่าง" (คนที่ชน ยุบไว้ ขยายได้), so that เทียบเฉพาะคนที่ใช้ได้จริง
10. As ฝ่ายประสานงาน, I want แผนกของแต่ละคนเป็นป้ายเล็กท้ายชื่อในโฟกัส และทุกแผนกขยายชั่วคราว, so that เห็นตัวเลือกทั้งหมดโดยไม่เสียข้อมูลแผนก
11. As ฝ่ายประสานงาน, I want คลิกเลนตัวเลือกแล้วถ้าขาดตำแหน่งเดียวให้ใส่ทันที ถ้าขาดหลายตำแหน่ง/ยังไม่กำหนดให้เลือกจากเมนู (ตำแหน่งที่ขาดขึ้นก่อน), so that จัดคนหนึ่งคนด้วยคลิกเดียวในกรณีปกติ
12. As ฝ่ายประสานงาน, I want การจัด/เอาออกบันทึกทันทีทุกครั้ง (ไม่มีแบบร่าง) และมี toast + ย้อนกลับเมื่อพลาด, so that ไม่ต้องจำว่ากดบันทึกหรือยัง
13. As ฝ่ายประสานงาน, I want คลิกแถบของคนที่จัดแล้วในงานโฟกัสเพื่อเอาออก, so that แก้ผิดได้ในที่เดียว
14. As ฝ่ายประสานงาน, I want ลำดับตัวเลือกไม่กระโดดระหว่างที่กำลังจัด, so that ไม่หลงว่ากดใครไป
15. As ฝ่ายประสานงาน, I want กลุ่มแผนกยุบเป็นค่าเริ่มต้น หัวกลุ่มบอก "ช่าง · 12 คน · ว่าง 9" และแผนกที่มีคนถูกจัดในวันนั้นขยายให้เอง, so that หน้าไม่ยาวแต่ยังเห็นภาพรวม
16. As ฝ่ายประสานงาน, I want ชิปกรองแผนก (เลือกได้หลายอัน จำในลิงก์ ค่าเริ่มต้นทุกแผนก), so that ดูเฉพาะแผนกที่เกี่ยวได้
17. As ฝ่ายประสานงาน, I want ตัวเลข "N งาน" ข้างชื่อทุกเลนคน (7 วันจากวันที่ดู) สีเข้มขึ้นตามจำนวน ทั้งโหมดวัน/สัปดาห์, so that เลือกคนที่ภาระน้อยกว่าได้
18. As ฝ่ายประสานงาน, I want ปุ่ม "ซ่อนคนว่าง" หายไป, so that ไม่เผลอซ่อนคนที่ต้องการเลือก
19. As คนหน้างาน (มือถือ), I want โฟกัสงานและคลิกจัดคนใช้ได้บนมือถือ, so that แก้แผนหน้างานได้
20. As ผู้ใช้ทุกคน, I want ตาราง/การ์ด/ไทม์ไลน์อัปเดตพร้อมกันหลังจัดคน, so that ทุกมุมมองตรงกัน
21. As ผู้ดูแลระบบ, I want รายการใน "มีอะไรใหม่", so that ทีมรู้วิธีใช้โฟกัสงาน

## Implementation Decisions

- **Schema**: คอลัมน์ `required_roles` jsonb บนงาน (lead) รูปแบบ `{ "<role value>": count }` ค่าว่าง = ยังไม่กำหนด; รวมใน migration `20260830_crm_leads_event_time.sql` ที่ยังไม่ได้รัน
- **Seam เดียว** (โมดูล logic บริสุทธิ์เดิม): `missingRoles(lead)` → รายการ `{ role, need, have }` ที่ยังขาด; `isFullyStaffed(lead)`; `getMissing` ใช้กติกาใหม่ (ไม่กำหนด → ≥1); `MISSING_LABELS.staff` ต่อท้ายด้วยตำแหน่งที่ขาด; `workloadOf(personId, leads, fromDate)` = จำนวนงานใน 7 วัน; `departmentSummary(layout)` = ต่อแผนก {คน, ว่าง}; `focusCandidates(lead, people, leads, fromDate)` → `{ candidates: [...เรียง], busy: [...] }` แต่ละรายการมี availability, workload, department; `layoutDay/layoutWeek` รับ `opts.departments` (กรอง) แทน `hideFree`
- **บันทึก**: ตำแหน่งที่ต้องการผ่าน `updateLeadTracking` (เพิ่มฟิลด์ `required_roles` ตรวจ role กับ staff_role ที่ active และ count 1–20); การจัด/เอาออกในโฟกัสส่งรายการเต็มของอีเวนต์เป้าหมายผ่าน `assignLeadStaff` ตัวเดิม (เพิ่ม/ลบ 1 คนแล้วส่งทั้งชุด) — อีเวนต์เป้าหมายใช้กติกาเดียวกับหน้าต่างจัดคน (1 อีเวนต์ → ใช้เลย, 0 → สร้าง, >1 → ใช้อีเวนต์ที่มีคนมากสุด และหัวโฟกัสมี Select ให้เปลี่ยน)
- **UI ตำแหน่งที่ต้องการ**: component เดียว (รายการ ตำแหน่ง × จำนวน + เพิ่ม/ลบ) ใช้ใน 3 ที่: การ์ดข้อมูลอีเวนต์ CRM (โหมดแก้ไข/แสดง), หัวโฟกัส (ปุ่มดินสอ → popover), หน้าต่างจัดคน (ส่วนบน)
- **โฟกัส** อยู่ใน URL `?focus=<leadId>`; เข้าโฟกัส = ขยายทุกแผนกชั่วคราว, freeze ลำดับตัวเลือก ณ ตอนเข้า (คำนวณใหม่เมื่อเปลี่ยนงาน/วัน/ออก); แถบเวลาโปร่งพาดทุกเลนตาม startMin–endMin ของงานโฟกัส; ออกโฟกัส = กลับสถานะยุบ/ชิปเดิม
- **ยุบแผนก**: state ในหน้า (ไม่ persist) ค่าเริ่มต้นยุบทั้งหมด ยกเว้นแผนกที่มีแถบในวัน/สัปดาห์ที่ดู; หัวกลุ่มคลิกสลับ; ชิปแผนก `?dept=a,b` ค่าว่าง = ทุกแผนก
- **ภาระงาน**: นับงานที่คนอยู่ใน 7 วันจากวันที่ดู (โหมดวันก็นับ 7 วัน) แสดงเป็นตัวเลขเล็กข้างชื่อ 0 = ไม่แสดง, 1–2 เทา, 3–4 เหลือง, ≥5 แดง
- ถอน `hideFree` และปุ่ม "ซ่อนคนว่าง"
- Actor ทำได้ทุกคนที่ล็อกอิน (เหมือน assignLeadStaff)

## Testing Decisions

- TDD ที่ seam: assert ก่อน (แดง) แล้วเขียน (เขียว) ใน check script เดิม รันด้วย tsx
- เคส: missingRoles (ครบ/ขาด/เกิน/ตำแหน่งอื่นเพิ่ม/ไม่กำหนด), getMissing ทั้งสองกติกา, ป้าย staff มีตำแหน่งที่ขาด, workloadOf ขอบ 7 วัน, departmentSummary นับว่าง, focusCandidates ลำดับ (availability แล้ว workload) + กลุ่ม busy, opts.departments กรองเลน
- UI ตรวจด้วยตา + tsc/eslint ไม่มี error ในไฟล์ที่แตะ; ปิดท้าย `/code-review`
