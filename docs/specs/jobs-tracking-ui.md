# Spec: หน้า "ติดตามงาน" (/jobs/tracking) — ตารางที่อ่านออกทันที

Status: ready-for-agent
Glossary: see `CONTEXT.md` (งาน, อีเวนต์, จัดคน, จัดรถ, สถานะออกแบบ, ความพร้อม, สิ่งที่ยังขาด, ซัพพลายเออร์)

## Problem Statement

ฝ่ายประสานงานเปิดหน้าติดตามงานแล้วต้องไล่อ่านทีละแถวจึงจะรู้ว่า งานไหนใกล้ถึง งานไหนยังขาดคน/รถ/แบบ ตารางปัจจุบันเป็นรายการแบนๆ ที่ปนงานที่จบไปแล้ว มี checkbox ที่ต้องตีความ และไม่มีตัวเลขสรุปใดๆ ทำให้ first impression ไม่บอกว่า "ต้องรีบทำอะไร" บนมือถือตารางกว้างเกินจอจนใช้หน้างานไม่ได้

## Solution

หน้าเดียวกันตอบ 3 คำถามพร้อมกันตั้งแต่แวบแรก: **งานไหนใกล้ถึง** (ชิปสรุปช่วงเวลา + หัวคั่นกลุ่ม + badge countdown), **แต่ละงานอยู่ขั้นไหน** (สถานะออกแบบมีสี), **ยังขาดทรัพยากรอะไร** (คอลัมน์ "ความพร้อม" ที่เขียนตรงๆ ว่าขาดอะไร และย้อมแถวแดงเมื่อใกล้ถึงแต่ยังไม่พร้อม) งานที่ผ่านไปแล้วถูกซ่อนโดยปริยาย บนจอแคบแต่ละงานกลายเป็นการ์ดที่แก้ไขได้ครบเท่าเดสก์ท็อป

## User Stories

1. As ฝ่ายประสานงาน, I want เห็นชิป "วันนี้ / 7 วันนี้ / เดือนนี้" พร้อมจำนวนงานและจำนวนที่ยังไม่พร้อม, so that รู้ภายใน 1 วินาทีว่าวันนี้ต้องรีบเคลียร์อะไร
2. As ฝ่ายประสานงาน, I want กดชิปเพื่อกรองตารางให้เหลือเฉพาะช่วงนั้น และกดซ้ำเพื่อยกเลิก, so that โฟกัสงานชุดเดียวโดยไม่ต้องเลื่อนหา
3. As ฝ่ายประสานงาน, I want งานถูกคั่นเป็นกลุ่ม "วันนี้ / 7 วันนี้ / 7 วันถัดไป / รายเดือน", so that สายตาแยกงานเร่งด่วนออกจากงานที่ยังมีเวลาได้ทันที
4. As ฝ่ายประสานงาน, I want ภายในกลุ่มเรียงตามวันแล้วตามเวลาเริ่มงาน, so that ลำดับตรงกับลำดับที่ต้องออกไปทำจริง
5. As ฝ่ายประสานงาน, I want งานที่ผ่านไปแล้วถูกซ่อนโดยปริยาย และมีปุ่มสลับ "แสดงงานที่ผ่านแล้ว", so that ตารางไม่รกด้วยงานที่ไม่ต้องติดตาม แต่ยังย้อนดูได้
6. As ฝ่ายประสานงาน, I want คอลัมน์ "งาน" แสดง วันที่ | เวลาเริ่ม (หรือ "ยังไม่ใส่เวลา"), badge นับถอยหลัง, และชื่อลูกค้า/สถานที่ที่กดไปหน้า CRM ได้, so that รู้ว่างานคืออะไร เมื่อไหร่ โดยไม่ต้องเปิดหน้าอื่น
7. As ฝ่ายประสานงาน, I want คอลัมน์ "ความพร้อม" เขียนว่า "พร้อม" หรือ "ขาด: ออกแบบ, จัดรถ, เวลาเริ่ม", so that ไม่ต้องตีความ checkbox ว่าต้องทำอะไรต่อ
8. As ฝ่ายประสานงาน, I want แถวที่ยังไม่พร้อมและอยู่ภายใน 7 วัน ย้อมแดงอ่อนพร้อมแถบซ้ายสีแดง, so that งานที่เสี่ยงหลุดกระโดดเข้าตาก่อนใคร
9. As ฝ่ายประสานงาน, I want งานที่ยังไม่พร้อมแต่ยังไกล แสดงเป็นสีเหลือง/ส้มเฉพาะช่องความพร้อม (ไม่ย้อมทั้งแถว), so that เห็นว่ามีงานค้างแต่ไม่ตกใจเกินเหตุ
10. As ฝ่ายออกแบบ, I want เปลี่ยนสถานะออกแบบจาก dropdown ในแถวได้ทันที และสีของช่องเปลี่ยนตาม, so that อัปเดตงานได้โดยไม่ออกจากหน้า
11. As ฝ่ายประสานงาน, I want เลือกรถจาก dropdown (ยังไม่จัดรถ / Mitsubishi Triton / Toyota Champ) ในแถว, so that การจัดรถถูกบันทึกและนับเข้าความพร้อมอัตโนมัติ
12. As ฝ่ายประสานงาน, I want ช่องจัดคนแสดงชื่อเล่นของทุกคนในช่องเลย และกดเปิดดูรายชื่อเต็ม "ชื่อเล่น | ชื่อจริง" แยกตามตำแหน่ง, so that รู้ว่าใครไปงานไหนโดยไม่ต้องกดเปิดทุกแถว
13. As ฝ่ายประสานงาน, I want คนที่ยังไม่ตั้งชื่อเล่นแสดงชื่อจริงแทน, so that ไม่มีช่องว่างหรือ "—" ที่ทำให้สับสน
14. As ฝ่ายประสานงาน, I want ช่องซัพพลายเออร์เป็นไอคอนดินสอ (สีเข้มเมื่อมีข้อมูล) กดแล้วเปิดหน้าต่างพิมพ์ข้อความหลายบรรทัด, so that บันทึกยาวๆ ได้โดยตารางไม่กว้างขึ้น
15. As ฝ่ายประสานงาน, I want หัวตารางและหัวหน้าอธิบายชัดว่า "งาน N งาน · ยังไม่พร้อม M", so that คนที่ไม่เคยเปิดหน้านี้เข้าใจว่าตารางสื่ออะไร
16. As คนหน้างาน (มือถือ), I want แต่ละงานเป็นการ์ด 1 ใบบนจอแคบ แสดงวันเวลา ลูกค้า สถานที่ นับถอยหลัง ความพร้อม, so that อ่านบนมือถือได้โดยไม่ต้องเลื่อนซ้ายขวา
17. As คนหน้างาน (มือถือ), I want แก้สถานะออกแบบ จัดรถ และซัพพลายเออร์ได้จากการ์ด, so that อัปเดตหน้างานได้ทันทีไม่ต้องรอกลับออฟฟิศ
18. As ผู้ใช้ทุกคน, I want การแก้ไขทุกอย่างสะท้อนบนหน้าทันที (ชิป กลุ่ม ความพร้อม สีแถว อัปเดตตาม) และมี toast แจ้งถ้าบันทึกไม่สำเร็จ, so that มั่นใจว่าสิ่งที่เห็นคือข้อมูลล่าสุด
19. As ผู้ใช้ทุกคน, I want หน้านี้แสดงถูกต้องทั้ง light/dark mode, so that สีเร่งด่วน/พร้อมอ่านออกในทุกธีม
20. As ผู้ใช้ทุกคน, I want เมื่อไม่มีงานในช่วงที่กรอง มีข้อความบอกชัด ("ไม่มีงานในช่วงนี้"), so that ไม่เข้าใจผิดว่าหน้าพัง
21. As ผู้ดูแลระบบ, I want เห็นรายการนี้ใน "มีอะไรใหม่", so that ทีมรู้ว่าหน้าเปลี่ยนไปอย่างไร

## Implementation Decisions

- **ไม่มีการเปลี่ยน schema เพิ่ม** — ทุกอย่างคำนวณจากข้อมูลที่มี (สถานะออกแบบ, จัดคนจาก event_staff ของอีเวนต์ที่ผูกกับงาน, key รถใน tracking_checklist, เวลาเริ่มงานจาก CRM) ยังต้องรัน migration `event_time`/`event_end_time` ที่ค้างจากงานก่อนหน้า
- **ความพร้อม** เป็นฟังก์ชันบริสุทธิ์จากข้อมูลแถว: พร้อมเมื่อ สถานะออกแบบ ∈ {ส่งEmail+CFลูกค้า, ส่งภาพ+เสร็จสมบูรณ์} ∧ จัดคน ≥ 1 ∧ จัดรถแล้ว ∧ มีเวลาเริ่มงาน; ผลลัพธ์คือรายการ "สิ่งที่ยังขาด" (ออกแบบ / จัดคน / จัดรถ / เวลาเริ่ม) — ว่าง = พร้อม ซัพพลายเออร์ไม่เกี่ยว
- **ช่วงเวลา** เป็น rolling นับจากวันนี้ (ไม่ใช่สัปดาห์ปฏิทิน): วันนี้ = 0 วัน, "7 วันนี้" = 1–7, "7 วันถัดไป" = 8–14, ถัดไปคั่นตามเดือนปฏิทิน (ชื่อเดือนไทย + ปี พ.ศ.); ชิป "เดือนนี้" = เดือนปฏิทินปัจจุบัน
- **งานที่ผ่านแล้ว** = วันจัดงาน (หรือวันสิ้นสุดถ้ามี) ก่อนวันนี้; ซ่อนโดยปริยาย, toggle เก็บใน state ของหน้า (ไม่ persist)
- **การกรองด้วยชิป** เป็น state ฝั่ง client บนข้อมูลที่โหลดมาแล้ว ไม่ยิง server ใหม่; ชิปเดียว active ได้ทีละอัน
- **ไฮไลต์ 2 ระดับ**: ยังไม่พร้อม → ช่องความพร้อมสีเหลือง/ส้ม; ยังไม่พร้อม ∧ อยู่ภายใน 7 วัน (รวมวันนี้และงานที่ผ่านแล้วถ้าเปิดดู) → ทั้งแถวแดงอ่อน + แถบซ้าย
- **ชื่อคน**: server ส่ง nickname และ full_name มาให้; ช่องตารางแสดงชื่อเล่น (fallback ชื่อจริง) คั่นด้วยจุลภาค; popover แสดง "ชื่อเล่น | ชื่อจริง" แยกตามตำแหน่ง
- **คอลัมน์เดสก์ท็อป 7 ช่อง** ตามลำดับ: ลำดับ | งาน | ออกแบบ | ซัพพลายเออร์ | จัดคน | จัดรถ | ความพร้อม (ยุบ Countdown เข้าช่องงาน, แทน checklist ด้วยความพร้อม)
- **มือถือ** (จอแคบกว่า md): ซ่อนตารางและ render การ์ดต่องานด้วย component แก้ไขชุดเดียวกัน (Select สถานะ, Select รถ, Dialog ซัพพลายเออร์) เพื่อไม่ให้ logic ซ้ำ; หัวคั่นกลุ่มและชิปใช้ร่วมกันทั้งสองโหมด
- **Optimistic update** ยังคงแบบเดิม: แก้ state ในหน้าทันที เรียก server action ต่อ ถ้า error แสดง toast
- ปุ่ม/ข้อความทั้งหมดใช้คำว่า "งาน" ตาม glossary; ตัด "checklist", "ดีล", "Countdown" ออกจาก UI

### ส่วนขยาย (2026-08-30): ชน/ต่อคิว + จัดคนในแถว

- **ความว่าง** คำนวณในแอมโมดูล seam เดิมจากข้อมูลที่มี: วันจัดงาน–วันสิ้นสุด, เวลาเริ่ม–สิ้นสุด, รถที่เลือก, คนจาก event_staff ของทุกงานที่ตอบรับแล้ว; ไม่มี schema ใหม่
- กติกา: วันทับกันก่อน → เวลาทับ = ชน, ชิดกัน (สิ้นสุด = เริ่ม) = ต่อคิว, งานหลายวันซ้อนกัน = ชน, ขาดเวลาเริ่ม/สิ้นสุดฝั่งใดฝั่งหนึ่ง = เช็คเวลาไม่ได้
- ป้ายชนแสดงใต้ช่องจัดรถ (1 ป้าย) และใต้ชื่อในช่องจัดคน (≤2 ป้าย + "+N") — สีแดง/เหลือง/เทาตามสถานะ
- **จัดคนในแถว**: กดช่องจัดคนเปิดหน้าต่าง เลือกคนต่อตำแหน่ง (ตำแหน่งจาก crm_settings staff_role) เห็นความว่างของแต่ละคนตอนเลือก มีตัวกรอง "แสดงเฉพาะคนว่าง" (ซ่อนเฉพาะคนที่ชน)
- เขียนลง event_staff ของอีเวนต์ที่ผูกกับงาน แบบลบ+ใส่ใหม่เฉพาะอีเวนต์นั้น แล้ว sync array ผู้รับผิดชอบใน CRM เหมือนหน้าแก้อีเวนต์; งานที่มีหลายอีเวนต์ให้เลือกอีเวนต์เป้าหมาย; ไม่มีอีเวนต์ → สร้างอีเวนต์ "main" จากข้อมูลงานให้อัตโนมัติ
- สิทธิ์: ทุกคนที่ล็อกอินจัดคน/สร้างอีเวนต์อัตโนมัติจากหน้านี้ได้ (ต่างจากหน้า Events ที่ admin-only) เพราะผู้ใช้หลักคือฝ่ายประสานงาน — บันทึก activity log ทั้งการสร้างอีเวนต์และการจัดคน

## Testing Decisions

- ไม่มี test runner ในโปรเจกต์ (ตาม CLAUDE.md) — ใช้ 2 ชั้น:
  1. **Self-check แบบรันได้** สำหรับ logic บริสุทธิ์ (ความพร้อม, การจัดกลุ่มช่วงเวลา, การนับชิป) เป็นไฟล์ `*.check.ts` ข้างโมดูล รันด้วย `npx tsx` ใช้ `assert` ล้วน ไม่มี framework — ทดสอบเฉพาะ input→output ไม่ทดสอบ React
  2. **ตรวจด้วยตา** ผ่าน `npm run dev` ทั้งเดสก์ท็อปและความกว้างมือถือ + `npx tsc --noEmit` ต้องไม่มี error ในไฟล์ที่แตะ
- **Seam เดียว**: แยก logic คำนวณ (readiness, grouping, chip counts) ออกเป็นโมดูลบริสุทธิ์ที่รับ `TrackingLead[]` + วันที่วันนี้ เป็น input — ทั้งตารางและการ์ดมือถือเรียกผ่าน seam นี้ ทดสอบที่ seam นี้จุดเดียว
- Prior art: ยังไม่มี test ในโค้ดเบส; รูปแบบ script รันตรงมีใน `scripts/` (tsx)

## Out of Scope

- ตารางรถแบบเพิ่ม/ลบจาก UI (รถยังเป็นค่าคงที่ 2 คัน)
- แก้ไขเวลาเริ่ม/สิ้นสุดงาน จากหน้านี้ (ทำที่ CRM เหมือนเดิม)
- มุมมอง "ตารางคนรายสัปดาห์" (แถว = คน/รถ, คอลัมน์ = วัน) — รอจนกว่าการจัดคนในแถวจะใช้จริงแล้วยังต้องเทียบข้ามงานบ่อย
- การ persist ตัวกรอง/toggle ข้ามการรีโหลด
- แจ้งเตือน (notification) เมื่องานใกล้ถึงแต่ยังไม่พร้อม
- การแปลภาษาอังกฤษของหน้านี้ (หน้านี้เป็นไทยล้วนอยู่แล้ว)
- เปลี่ยน route enforcement ใน proxy.ts
