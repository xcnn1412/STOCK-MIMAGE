# บอร์ดวันงาน (Day-of board) — ปรับ /jobs ให้เลิกซ้ำซ้อนกับพูลงาน

## Problem Statement

หลังพูลงานกินบทบาท "วางแผน/รับงาน" ไปหมด หน้า /jobs เหลือความซ้ำซ้อนชิ้นสุดท้าย: บอร์ด kanban ฝั่งกราฟิกที่อัปเดตสถานะซ้ำกับสถานะออกแบบรายใบในพูล ทีมสับสนว่าต้องไปหน้าไหน และสถานะวันงานจริง (ออกหน้างาน) ต้องลากมือทั้งที่ระบบรู้จากเช็คอินอยู่แล้ว

## Solution

/jobs กลายเป็น **บอร์ดวันงาน** (ดู CONTEXT.md): kanban ใบงานหน้างานอย่างเดียวช่วง 7 วันข้างหน้า + ชิป "วันนี้", สถานะ "ออกหน้างาน" ขยับเองเมื่อทีมเช็คอินหน้างานครั้งแรกของอีเวนต์, แถบ**ใบงานลอย**แยกใต้บอร์ด, การ์ดพูลมีปุ่มเปิดหน้าใบงาน (คอมเมนต์/@mention), เมนูเปลี่ยนชื่อเป็น "บอร์ดวันงาน" — แบ่งบทบาทขาด: พูล = วางแผน/รับงาน · บอร์ดวันงาน = ปฏิบัติการวันจริง

## User Stories

1. As a หัวหน้างาน, I want บอร์ดเปิดมาเห็นเฉพาะใบงานหน้างานช่วง 7 วันข้างหน้า, so that จอไม่รกด้วยงานไกลตัว
2. As a หัวหน้างาน, I want ชิป "วันนี้" จิ้มเดียวเหลือแต่งานวันนี้, so that ใช้ตอนอยู่หน้างานได้ทันที
3. As a หัวหน้างาน, I want บอร์ดกราฟิกหายไป, so that ไม่มีสถานะสองชุดให้อัปเดตซ้ำ (สถานะออกแบบอยู่ในพูลรายใบแล้ว)
4. As a ระบบ, I want ใบงานหน้างานเลื่อนเป็น "ออกหน้างาน" เองเมื่อทีมเช็คอินหน้างานครั้งแรกของอีเวนต์ที่ผูกกับงาน, so that บอร์ดสะท้อนความจริงโดยไม่ต้องลากมือ (ขนของ/เก็บงานยังลากมือ — ไม่มีสัญญาณจริงให้เกาะ)
5. As a แอดมิน, I want แถบ "ใบงานลอย" (ไม่ผูก CRM) แยกใต้บอร์ดพร้อมปุ่มสร้างงานเดิม, so that งานนอกสาย CRM ไม่เงียบหาย (พูลมองไม่เห็นโดยดีไซน์)
6. As a สมาชิกทีม, I want ปุ่ม "เปิดหน้าใบงาน" บนการ์ดใบงานในพูล, so that กระโดดไปคุยงาน (คอมเมนต์/@mention) ในหน้าใบงานได้ทันที
7. As a ผู้ใช้, I want เมนูเปลี่ยนชื่อจาก Jobs เป็น "บอร์ดวันงาน", so that ไม่งงว่าต่างจาก "ติดตามงาน" อย่างไร
8. As a ผู้ใช้เดิม, I want /jobs/[id], /jobs/settings, /jobs/tracking และลิงก์จากกระดิ่งทำงานเหมือนเดิมทุกอย่าง, so that ไม่มีอะไรพัง

## Implementation Decisions

- บอร์ดหลักของ /jobs กรอง job_type = onsite เท่านั้น; ช่วงเวลาเริ่มต้น = วันนี้ถึง +7 วัน (อิงวันงานของงาน/lead ที่ผูก; ใบงานไม่มีวัน = แสดงในใบงานลอยหรือช่วงปัจจุบัน) + ชิป "วันนี้" / "ทั้งหมด"
- สถานะอัตโนมัติ: hook ในการเช็คอิน onsite (check-in action) — เช็คอินหน้างานครั้งแรกของอีเวนต์ → jobs onsite ของ lead ที่ผูกอีเวนต์นั้น ที่สถานะยังอยู่ก่อน "ออกหน้างาน" เลื่อนเป็น 'onsite' + log ActionType ใหม่ + ห้ามล้มการเช็คอิน (try/catch แบบเดียวกับ hook อื่น)
- ใบงานลอย = jobs ที่ crm_lead_id เป็น null (ทุก job_type) — แถบแยกใต้บอร์ด
- ปุ่มบนการ์ดพูล (กราฟิก/หน้างาน) ลิงก์ไป /jobs/[id]
- เมนูใน nav-config เปลี่ยน label เป็น "บอร์ดวันงาน" (key/สิทธิ์ module เดิม)
- ไม่แตะ schema ไม่มี migration

## Testing Decisions

- Seam เดิม: pure logic (กรองช่วงวัน, จัดกลุ่มใบงานลอย, เงื่อนไข auto-advance) ใน tracking-logic หรือ module ข้าง jobs view + assert ใน check file
- ที่เหลือ `npx tsc --noEmit` + `npm run build` + เปิดหน้าจริง
