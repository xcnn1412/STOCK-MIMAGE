# จับชุดเอกสาร — รวมใบเบิกกับไฟล์แนบเป็น PDF ชุดเดียวสำหรับพิมพ์เข้าแฟ้ม

ตัดสินใจกับเจ้าของ 2026-09-29 · สถานะ: **สร้างและตรวจแล้ว** (v1.23.1 = ขั้น 0, v1.24.0 = ขั้น 1–4) ยังไม่เคยเปิดในเบราว์เซอร์ที่ล็อกอินจริง · ศัพท์: `CONTEXT.md` หัวข้อ "จับชุดเอกสาร" · schema: `supabase/migrations/20260929_claim_filed.sql` (ทดสอบกับ postgres 17 แล้ว 19 ข้อ)

## Problem Statement

ใบเบิกทุกใบที่ทำเสร็จต้องพิมพ์เป็นกระดาษเข้าแฟ้มของ office ตอนนี้ต้องเปิดใบเบิก กด "ส่งออก PDF" พิมพ์ แล้วเปิดใบเสร็จและใบกำกับภาษีทีละไฟล์มาพิมพ์ต่อ เดือนละ 127–361 ใบ (เฉลี่ยราว 230) ไฟล์แนบใบละ 3 ไฟล์โดยประมาณ ไม่มีที่บอกว่าใบไหนพิมพ์แล้ว

## Solution

ปุ่ม **จับชุดเอกสาร** รวมหน้าใบเบิก + เอกสารแนบ + ใบกำกับภาษี เป็น PDF ไฟล์เดียวพร้อมพิมพ์ ทำได้ทั้งทีละใบ (จากหน้าใบเบิก) และหลายใบ (เลือกจากรายการ แบ่งไฟล์ละไม่เกิน 20 ใบ) เลือกการวางหน้าได้ตอนจับชุด และทำเครื่องหมาย **เข้าแฟ้มแล้ว** เพื่อกันพิมพ์ซ้ำหรือตกหล่น

## User Stories

1. As a แอดมินการเงิน, I want กดปุ่มเดียวในหน้าใบเบิกแล้วได้ PDF ที่มีใบเบิกและไฟล์แนบครบ, so that ไม่ต้องเปิดพิมพ์ทีละไฟล์
2. As a แอดมินการเงิน, I want เลือกใบเบิกหลายใบจากรายการแล้วจับชุดรวดเดียว, so that พิมพ์ของทั้งเดือนได้ในไม่กี่คลิก
3. As a แอดมินการเงิน, I want เลือกว่าจะวางไฟล์ละหน้าหรือรูป 2 รูปต่อหน้า, so that เลือกได้ระหว่างอ่านง่ายกับประหยัดกระดาษ
4. As a แอดมินการเงิน, I want ให้ใบเบิกใหม่เริ่มที่แผ่นใหม่เมื่อพิมพ์สองหน้า, so that เอกสารของสองใบไม่อยู่บนกระดาษแผ่นเดียวกัน
5. As a แอดมินการเงิน, I want รู้ก่อนพิมพ์ว่าไฟล์ไหนรวมเข้าชุดไม่ได้, so that ไปพิมพ์ไฟล์นั้นแยกและชุดไม่ขาด
6. As a คนจัดแฟ้ม, I want ทุกหน้าไฟล์แนบมีเลขที่ใบเบิกและลำดับหน้า, so that กระดาษที่หลุดเรียงกลับได้
7. As a แอดมินการเงิน, I want ทำเครื่องหมายว่าเข้าแฟ้มแล้วและกรองดูใบที่ยังไม่เข้าแฟ้ม, so that ไม่พิมพ์ซ้ำและไม่มีใบตกหล่น
8. As a แอดมินการเงิน, I want เห็นคำเตือนเมื่อไฟล์แนบเปลี่ยนหลังเข้าแฟ้ม, so that รู้ว่าต้องพิมพ์ใหม่
9. As a พนักงาน, I want จับชุดเอกสารของใบเบิกตัวเองได้, so that เตรียมเอกสารส่ง office เองได้
10. As a แอดมิน, I want แท็บชำระเงินแล้วแสดงครบทุกใบ, so that จับชุดย้อนหลังได้และยอดรวมถูกต้อง

## Implementation Decisions

### ตัดสินใจกับเจ้าของแล้ว

| เรื่อง | คำตอบ |
|---|---|
| ขอบเขตรอบแรก | ทีละใบ + หลายใบ |
| ติดตามการเข้าแฟ้ม | ต้องการ (มี migration) |
| การวางหน้า | ให้เลือกได้ตอนจับชุด: ไฟล์ละหน้า หรือ รูป 2 รูปต่อหน้า |

### ตัดสินใจโดยผู้วางแผน (แจ้งเจ้าของแล้ว เปลี่ยนได้)

- ลำดับในชุด: หน้าใบเบิก → ใบเสร็จ/เอกสารแนบ → ใบเสร็จตอนเคลียร์เงินทดลองจ่าย → ใบกำกับภาษี → สลิปคืนเงิน (เฉพาะไฟล์ที่หน้าใบเบิกยังไม่ได้ฝังไว้ คือไฟล์ PDF)
- จับชุดทีละใบ: สิทธิ์เดียวกับ `/api/pdf/payment-voucher` (แอดมิน, เจ้าของใบ, เอกสารเงินสดย่อยทุกคน) · จับชุดหลายใบและทำเครื่องหมายเข้าแฟ้ม: แอดมินเท่านั้น
- จับชุดได้ทุกสถานะ ใบที่เอกสารยังไม่ครบ (`getClaimChecklist`) ขึ้นคำเตือนในหน้าสรุป แต่ไม่ห้าม
- ไม่เก็บไฟล์ชุดเอกสารในสตอเรจ สร้างสดทุกครั้ง (พื้นที่เก็บไฟล์เคยเต็ม — ดู memory storage-cleanup)
- ใบวงเงินสดย่อย: ชุด = ใบสรุปประจำเดือน + ไฟล์ของใบนั้นเอง · ค่าใช้จ่ายจากกล่องเป็นใบเบิกของตัวเอง จับชุดแยก
- หลายใบในไฟล์เดียวเรียงตามเลขที่ใบเบิกจากน้อยไปมาก

```ts
type BundleFileKind = 'receipt' | 'settlement' | 'tax_invoice' | 'refund_slip'
type BundleFailReason = 'fetch' | 'foreign-host' | 'too-large' | 'unsupported' | 'broken'
interface BundleInputFile {
  kind: BundleFileKind
  index: number            // ลำดับในชนิดเดียวกัน เริ่มที่ 1
  total: number
  note?: string            // เลขที่ใบกำกับภาษี
  bytes: Uint8Array | null // null = ดึงไม่ได้ (ต้องมี failReason)
  failReason?: BundleFailReason
}
interface BundleClaimInput { claimNumber: string; voucher: Uint8Array; files: BundleInputFile[] }
interface BundleOptions { layout: 'one' | 'two'; duplex: boolean }
interface BundleReport {
  pages: number
  claims: { claimNumber: string; pages: number; included: number
            failed: { kind: BundleFileKind; index: number; reason: BundleFailReason }[] }[]
}
function sniffFileType(bytes: Uint8Array): 'pdf' | 'jpeg' | 'png' | 'unsupported'
function planPages(claims, options): PlannedPage[]   // ล้วน ตรวจได้โดยไม่ต้องสร้าง PDF
async function buildBundle(claims: BundleClaimInput[], options: BundleOptions): Promise<{ pdf: Uint8Array; report: BundleReport }>
```

### กติกาการประกอบหน้า

| เรื่อง | กติกา |
|---|---|
| ชนิดไฟล์ | ดูจากหัวไฟล์ (magic bytes) ไม่ดูนามสกุล |
| หน้าใบเบิก | คัดลอกทุกหน้าตามเดิม ไม่ย่อ ไม่มีแถบหัวกระดาษเพิ่ม |
| รูป (`layout: 'one'`) | A4 แนวตั้ง รูปละหน้า ย่อให้พอดีกรอบเนื้อหา คงสัดส่วน ไม่ขยายเกินขนาดจริง 2 เท่า |
| รูป (`layout: 'two'`) | รูปที่อยู่ติดกันของใบเบิกเดียวกันจับคู่บน-ล่างในหน้าเดียว แต่ละครึ่งมีแถบของตัวเอง รูปเดี่ยวที่เหลืออยู่ครึ่งบน |
| PDF แนบ | ทุกหน้าของไฟล์ หน้าละหน้าเสมอ (ทั้งสอง layout) ย่อให้พอดีกรอบเนื้อหาของ A4 คงสัดส่วน |
| แถบหัวกระดาษ | `<เลขที่ใบเบิก> · <ชนิด> <ลำดับ>/<ทั้งหมด> · หน้า <n>/<หน้าทั้งหมดของใบเบิกนี้>` ใบกำกับภาษีต่อท้ายด้วยเลขที่ที่บันทึกไว้ เนื้อหาเริ่มใต้แถบ ไม่ถูกทับ |
| ไฟล์ที่รวมไม่ได้ | ใส่หน้าแจ้ง 1 หน้า: ชนิด ลำดับ สาเหตุ และข้อความ "ต้องพิมพ์ไฟล์นี้แยก" — ห้ามข้ามเงียบ |
| PDF ล็อกรหัส/เสีย | `failReason: 'broken'` → หน้าแจ้ง |
| พิมพ์สองหน้า (`duplex`) | ใบเบิกที่จำนวนหน้าเป็นเลขคี่ต่อท้ายด้วยหน้าว่าง 1 หน้า (มีผลเมื่อมีมากกว่า 1 ใบ) |

| เรื่อง | กติกา |
|---|---|

### หน้าจอ

- **หน้าใบเบิก:** ปุ่ม "จับชุดเอกสาร" ข้าง "ส่งออก PDF" → หน้าต่าง: เลือกการวางหน้า → กำลังจับชุด → สรุป (จำนวนหน้า, ไฟล์ที่รวมไม่ได้, เอกสารที่ยังขาด) → "เปิด PDF" · แอดมินเห็นสถานะเข้าแฟ้มและปุ่มทำ/ยกเลิกเครื่องหมาย
- **หน้ารายการ — ใบเดียว:** ทุกแถวมีปุ่ม "จับชุด" ของใบนั้น (ผู้ที่เห็นใบนั้นได้กดได้) เปิดหน้าต่างเดียวกับในหน้าใบเบิก ไม่ต้องเข้าไปในใบก่อน
- **หลายใบ = หลายชุดเรียงต่อกันในไฟล์เดียว:** แต่ละใบยังเป็นชุดของตัวเอง ขึ้นต้นด้วยหน้าใบเบิกของใบนั้น ตามด้วยไฟล์แนบของใบนั้น ไม่ปนกับใบอื่น (เจ้าของยืนยัน 2026-09-29: ต้องเลือกได้ทั้งเฉพาะใบ และหลายใบ)
- **หน้ารายการ (แอดมิน):** ปุ่ม "เลือกหลายใบ" → ช่องติ๊กหน้าแต่ละแถว + "เลือกทุกใบที่กรองอยู่" → แถบล่าง "จับชุดเอกสาร (N ใบ)" → หน้าต่าง: การวางหน้า + พิมพ์สองหน้า → แบ่งชุดละ 20 ใบ ทำทีละชุด แสดง "ชุดที่ 2/5" → แต่ละชุดมี "เปิด PDF" และ "ทำเครื่องหมายว่าเข้าแฟ้มแล้ว (20 ใบ)"
- **ตัวกรอง:** "ยังไม่เข้าแฟ้ม" / "เข้าแฟ้มแล้ว" (`filed=no|yes` ใน query string) · ป้าย "เข้าแฟ้มแล้ว" ในแถว
- PDF เปิดจาก blob ด้วยการกดปุ่มของผู้ใช้เอง (ไม่เปิดอัตโนมัติหลังโหลด — กันตัวบล็อกป๊อปอัป)

ปัญหาที่พบ: `getClaims()` ได้แถวสูงสุด 1,000 แถวล่าสุด แท็บ "ชำระเงินแล้ว" และหน้าคลังเก็บเห็น 1,000 จาก 1,598 ใบ (ใบที่สร้างก่อน 2026-06-22 หาย) ใบที่ถูกปฏิเสธรุ่นเก่า 24 ใบไม่อยู่ในรายการ

- `getClaims` อ่านเป็นหน้า หน้าละ 1,000 จนครบ ไม่ตัดเงียบ
- หน้ารายการโหลดเฉพาะใบที่ยังไม่จบ (ไม่ใช่ paid / cancelled / refund_confirmed) + เงินทดลองจ่ายที่จ่ายแล้วแต่ยังไม่เคลียร์ + วงเงินสดย่อยที่ยังเปิด
- แท็บ "ชำระเงินแล้ว" โหลดทีละเดือนจาก server (ค่าเริ่มต้น = เดือนล่าสุดที่มีการจ่าย) เปลี่ยนเดือน = โหลดใหม่ · การ์ด "ยอดรวมทั้งหมด" เปลี่ยนเป็นยอดของเดือนที่เลือก
- เหตุผลที่ไม่โหลดทั้งหมดมาที่ browser: ข้อมูลครบทุกใบราว 5MB ต่อการเปิดหน้า และโตเดือนละ ~230 ใบ

## Further Notes

### เสนอเพิ่ม (ยังไม่ทำจนกว่าเจ้าของสั่ง)

- ใบนำส่งเอกสารเป็นหน้าแรกของชุดหลายใบ: ตารางเลขที่ใบเบิก ผู้เบิก หัวข้อ ยอดสุทธิ จำนวนหน้า และช่องเซ็นรับ
- จับชุดทั้งเดือนจากแท็บชำระเงินแล้วด้วยปุ่มเดียว ("จับชุดใบที่ยังไม่เข้าแฟ้มของเดือนนี้")

### สิ่งที่ต่างจากแผนตอนลงมือ (2026-09-29)

- **เพดานขนาดรวม 100MB ต่อคำขอ** (เพิ่มโดยผู้ตรวจ): pdf-lib ใช้หน่วยความจำหลายเท่าของขนาดไฟล์ ใบที่แนบ PDF สแกนหลายสิบไฟล์ทำให้ server ล้มได้ — เกินเพดานได้ 413 และหยุดดึงไฟล์ที่เหลือ
- **หัว `X-Bundle-Report` ใส่รายการไฟล์ที่รวมไม่ได้ไม่เกิน 50 รายการ** พร้อม `failedTotal` (เพิ่มโดยผู้ตรวจ): ถ้าสตอเรจล่ม ทุกไฟล์ล้มพร้อมกันและหัว HTTP จะใหญ่จน proxy ทิ้งคำตอบ ตัว PDF มีหน้าแจ้งครบเสมอ
- **ข้อความและชนิดข้อมูลที่หน้าจอใช้อยู่ใน `lib/claim-bundle-labels.ts`** (ไฟล์ที่ไม่ import อะไร) — client component ห้าม import `lib/claim-bundle.ts` เพราะลาก pdf-lib และ react-pdf ไปที่ browser
- **ตัวกรองเข้าแฟ้มมี 4 ค่า**: ทุกสถานะแฟ้ม / ยังไม่เข้าแฟ้ม / เข้าแฟ้มแล้ว / ไฟล์แนบเปลี่ยนหลังเข้าแฟ้ม (`filed=no|yes|changed`)
- **เลือกหลายใบได้ครั้งละไม่เกิน 200 ใบ** (10 ไฟล์) — กันหน่วยความจำของเบราว์เซอร์
- **หน้า PDF แนบ**: เคารพ `/Rotate` ของหน้า ใช้กรอบที่มองเห็น (CropBox ∩ MediaBox) หน้าว่างที่ไม่มีเนื้อหารวมได้เป็นหน้าว่างพร้อมแถบ · PDF ที่ไม่มี `%%EOF` ใน 1KB ท้ายไฟล์ถือว่าดาวน์โหลดไม่ครบ (`broken`)
- **ตำแหน่งรูป**: กึ่งกลางแนวนอน ชิดบนของกรอบ · PDF แนบขยายให้เต็มกรอบได้ (เป็นเวกเตอร์) รูปขยายไม่เกิน 2 เท่า
- **หน้าแจ้งมีแถบหัวกระดาษด้วย** และนับรวมในเลขหน้าของชุด
- **ช่อง `tax_invoice_urls` ที่เป็นข้อความว่าง** (ใบกำกับที่กรอกแต่เลขที่ ไม่มีไฟล์) ไม่นับเป็นไฟล์ ทั้งในชุดเอกสารและในจำนวนไฟล์ของเครื่องหมายเข้าแฟ้ม
- **สลิปคืนเงิน**: ไฟล์ที่ path ลงท้าย `.pdf` เข้าชุดเอกสาร ที่เหลือฝังในหน้าใบเบิก — สลิปหนึ่งไฟล์จึงอยู่ที่เดียวเสมอ · สลิปที่อยู่เว็บอื่นไม่ถูกดึงอีกต่อไป (เดิมหน้าใบเบิกดึงทุก URL)
- **ลำดับการตรวจของ route**: 400 → 403 → 404 · พนักงานที่ขอหลายใบถูกปฏิเสธก่อนอ่านฐานข้อมูล
- **ลำดับเลขที่ใบเบิกเทียบเป็นตัวเลข** ทั้งฝั่งหน้าจอและ route (ใบที่ 1000 ของเดือนมาหลัง 999)
- **`paidMonth` ถูกตรวจก่อนตรวจตัวตน** ใน `getClaims`: ค่าเดือนผิดรูปแบบไม่ทำให้เกิดการอ่านตารางใดเลย

### ข้อจำกัดที่รู้

- ใบเสร็จยาว (กระดาษความร้อน) ที่เป็น PDF ถูกย่อให้พอดีหน้าเดียว ตัวหนังสือเล็กลง
