## Problem Statement

ทีมทำงานตาม flow: แอดมินสร้าง CRM → ลูกค้าตอบรับ → ส่งงานให้ทีมกราฟิกและทีมหน้างาน → จัดคน จัดกระเป๋า ออกงาน — แต่ระบบไม่มี "จุดส่งต่อ" จริง: การ์ด CRM โผล่บนหน้าติดตามงานเองโดยไม่มีใครกดรับ, ไม่มีการแจ้งเตือนทีมเมื่องานใหม่เข้า, ไม่รู้ว่าใครเป็นเจ้าของงานแต่ละฝ่าย, กระเป๋าอุปกรณ์ผูกอีเวนต์ได้ทีละงานจึงวางแผนล่วงหน้าไม่ได้ และการจัดกระเป๋าขาออกไม่ถูกบันทึก (ติ๊กแล้วหาย พิสูจน์ย้อนหลังไม่ได้)

## Solution

เปลี่ยนหน้าติดตามงาน (/jobs/tracking) เป็น **พูลงานกลาง**: เมื่อการ์ด CRM เป็น "ตอบรับ" ระบบสร้าง**ใบงาน** 2 ใบอัตโนมัติ (กราฟิก + หน้างาน) เข้าพูลพร้อมแจ้งเตือนทีมของฝ่ายนั้น สมาชิกฝ่ายกด**รับงาน**จากพูล (กราฟิก = เจ้าของงานออกแบบ, หน้างาน = หัวหน้างาน) ทีมหน้างาน**จองกระเป๋า**ให้อีเวนต์ล่วงหน้าได้จากพูล การจัดกระเป๋าถูกบันทึกถาวร ไทม์ไลน์เพิ่ม**เลนกระเป๋า**พร้อมตรวจชน และใบงานจบเองตามความจริง (กราฟิกจบตามสถานะออกแบบ / หน้างานจบเมื่อปิดอีเวนต์คืนกระเป๋า) — ศัพท์ทั้งหมดตาม CONTEXT.md (งาน, ใบงาน, พูลงาน, รับงาน, จองกระเป๋า, จัดกระเป๋า, ข้ามใบงาน, คืนงาน)

## User Stories

1. As a แอดมิน, I want ใบงานกราฟิกและใบงานหน้างานถูกสร้างอัตโนมัติเมื่อการ์ด CRM เปลี่ยนเป็น "ตอบรับ", so that ไม่ต้องกดส่งต่องานเองและไม่มีงานตกหล่น
2. As a แอดมิน, I want ระบบกันสร้างใบงานซ้ำเมื่อสถานะถูกสลับไปมา, so that พูลไม่มีใบงานผีซ้ำซ้อน
3. As a สมาชิกฝ่ายออกแบบ, I want ได้รับแจ้งเตือนกระดิ่งเมื่อมีใบงานกราฟิกใหม่เข้าพูล, so that รู้ทันทีโดยไม่ต้องเปิดหน้าจอค้างไว้
4. As a สมาชิกทีมหน้างาน, I want ได้รับแจ้งเตือนกระดิ่งเมื่อมีใบงานหน้างานใหม่เข้าพูล, so that เตรียมวางแผนอุปกรณ์และคนได้เร็ว
5. As a สมาชิกฝ่ายออกแบบ, I want กดรับใบงานกราฟิกจากพูลเป็นเจ้าของงาน, so that ทีมรู้ว่าใครทำงานชิ้นไหน ไม่หยิบซ้ำกัน
6. As a สมาชิกทีมหน้างาน, I want กดรับใบงานหน้างานเป็นหัวหน้างานผู้รับผิดชอบ, so that มีคนรับผิดชอบหลักต่องานชัดเจน ส่วนลูกทีมยังจัดผ่านระบบจัดคนเดิม
7. As a ผู้รับใบงาน, I want เห็นชื่อตัวเองบนใบงานและกรองดูเฉพาะงานของฉันได้, so that โฟกัสงานตัวเองได้ในพูลที่มีหลายงาน
8. As a ผู้รับใบงาน, I want คืนงานกลับเข้าพูลได้เมื่อไม่ว่าง, so that งานไม่ค้างอยู่กับคนที่ทำต่อไม่ได้
9. As a แอดมิน/ฝ่ายประสานงาน, I want เปลี่ยนคนรับใบงานได้ทุกเมื่อ, so that จัดการงานแทนได้เมื่อคนรับหายไป
10. As a แอดมิน/ฝ่ายประสานงาน, I want ข้ามใบงานที่ไม่ต้องทำ (เช่น ลูกค้าออกแบบเอง), so that พูลแสดงเฉพาะงานที่ต้องทำจริง
11. As a แอดมิน/ฝ่ายประสานงาน, I want ได้รับแจ้งเตือนเมื่อมีคนรับ/คืน/ข้ามใบงาน, so that เห็นความเคลื่อนไหวของพูลโดยไม่ต้องไล่ถาม
12. As a ฝ่ายประสานงาน, I want แท็บภาพรวมที่เห็นทุกงานแบบตารางเดิม (มุมมองต่องาน), so that ยังเห็นภาพรวมทุกฝ่ายในแถวเดียวเหมือนที่ใช้อยู่
13. As a สมาชิกฝ่ายออกแบบ, I want แท็บใบงานกราฟิกที่แสดงเฉพาะงานฝ่ายฉัน พร้อมสถานะออกแบบที่แก้ inline ได้, so that ทำงานได้ครบในแท็บเดียว
14. As a สมาชิกทีมหน้างาน, I want แท็บใบงานหน้างานที่แสดงจัดคน จัดรถ และกระเป๋า, so that เห็นความพร้อมของงานฝ่ายฉันครบในที่เดียว
15. As a ใบงานกราฟิก, I want จบออกจากพูลอัตโนมัติเมื่อสถานะออกแบบถึง "ส่งEmail+CFลูกค้า" หรือ "ส่งภาพ+เสร็จสมบูรณ์", so that พูลเหลือแต่งานที่ยังไม่เสร็จ
16. As a ใบงานหน้างาน, I want จบอัตโนมัติเมื่ออีเวนต์ถูกปิดจากการคืนกระเป๋า, so that ไม่มีงานค้างสถานะตลอดกาลโดยไม่มีใครลาก
17. As a สมาชิกทีมหน้างาน, I want จองกระเป๋าให้อีเวนต์ของงานจากพูลโดยตรง, so that ไม่ต้องอ้อมไปหน้าแก้ไขอีเวนต์
18. As a สมาชิกทีมหน้างาน, I want จองกระเป๋าใบเดียวให้หลายอีเวนต์คนละวันล่วงหน้าได้, so that วางแผนอุปกรณ์ทั้งสัปดาห์ได้
19. As a สมาชิกทีมหน้างาน, I want เห็นทันทีว่ากระเป๋าถูกจองสองงานวันเดียวกัน (ชน), so that แก้ปัญหาอุปกรณ์ไม่พอก่อนถึงวันงาน
20. As a สมาชิกทีมหน้างาน, I want การจัดกระเป๋า (เช็คของครบทุกชิ้น) ถูกบันทึกว่าใครจัด เมื่อไหร่, so that มีหลักฐานตอนของหายว่าขาออกเช็คครบ
21. As a สมาชิกทีมหน้างาน, I want สถานะจัดกระเป๋ารีเซ็ตเมื่อการจองถูกย้ายไปอีเวนต์อื่น, so that ไม่มีกระเป๋า "จัดครบ" ปลอมจากงานก่อน
22. As a ฝ่ายประสานงาน, I want "กระเป๋าจัดครบ" เป็นเกณฑ์ความพร้อมข้อที่ 5 และขึ้นใน "สิ่งที่ยังขาด", so that ความพร้อมของงานสะท้อนอุปกรณ์จริงไม่ใช่แค่คนกับรถ
23. As a ฝ่ายประสานงาน, I want เลนกระเป๋าบนไทม์ไลน์ (กระเป๋า 1 ใบ = 1 เลน แถบ = อีเวนต์ที่จอง สี = ยังไม่จัด/จัดครบ), so that เห็นภาระกระเป๋าทั้งสัปดาห์เหมือนที่เห็นคนและรถ
24. As a ฝ่ายประสานงาน, I want งานที่ยังไม่ใส่เวลาเริ่ม/สิ้นสุดขึ้นป้ายเตือนบนใบงานและไทม์ไลน์, so that ถูกกระตุ้นให้ใส่เวลาให้ชัดโดยไม่โดนกระดิ่งรบกวน
25. As a แอดมิน, I want ตั้งค่าในหน้า /jobs/settings ว่าแผนกไหนรับใบงานประเภทไหนและแผนกไหนจอง/ย้ายกระเป๋าได้, so that ปรับทีมได้เองภายหลังโดยไม่ต้องแก้โค้ด
26. As a แอดมิน, I want ค่าเริ่มต้นของทีม (กราฟิก=ฝ่ายออกแบบ, หน้างาน=ทีมออกหน้างาน+สตาฟ+ช่าง), so that ระบบใช้งานได้ทันทีก่อนเข้าไปตั้งค่า
27. As a แอดมิน, I want งาน accepted เดิมที่ยังไม่จบ (อีเวนต์ยังไม่ปิด วันงานยังไม่ผ่าน) ถูกสร้างใบงานย้อนหลัง, so that พูลวันแรกมีงานจริงครบ ทีมเชื่อบอร์ดได้ทันที
28. As a ผู้ใช้ทุกคน, I want การกระทำสำคัญ (สร้าง/รับ/คืน/ข้าม/จบใบงาน, จอง/ย้าย/จัดกระเป๋า) ถูกบันทึกใน activity log, so that ตรวจสอบย้อนหลังได้

## Implementation Decisions

- **พูลงานอ่านจากตาราง jobs ไม่ใช่ crm_leads** (ADR-0002) — ใบงาน = แถวในตาราง jobs (job_type: graphic/onsite) ข้อมูลลูกค้า/วันงาน join ผ่าน crm_lead_id; ฟิลด์ inline ระดับงาน (design_status, tracking_checklist, required_roles) คงอยู่ที่ crm_leads
- **จองกระเป๋าผ่านตารางใหม่ event_kits** (ADR-0003) — คอลัมน์หลัก: event_id, kit_id, packed_at, packed_by; unique ต่อคู่; ชน = จองสองอีเวนต์วันเดียวกัน (ไม่ดูเวลา ไม่มีต่อคิว); kits.event_id เดิมคงไว้เพื่อ flow เช็ค/คืนเดิม
- **Trigger อัตโนมัติ**: hook ใน updateLeadStatus เมื่อ newStatus = accepted → เรียก createJobsFromLead (มี guard กันซ้ำ: มี jobs ของ lead แล้วไม่สร้างใหม่) + แจ้งเตือนทีม
- **สถานะใบงานเริ่มต้น "รอรับงาน"** เพิ่มผ่าน job_settings (dynamic statuses ที่มีอยู่) ทั้ง status_graphic และ status_onsite ไม่แตะ schema สถานะ
- **รับงาน**: server action แบบ conditional update (รับได้เฉพาะสถานะรอรับงาน กัน race); กราฟิก = ผู้รับเข้า assigned_to/assigned_graphics, หน้างาน = ผู้รับเป็นหัวหน้างาน (ฟิลด์ระบุหัวหน้าบนใบงาน) ลูกทีมใช้ event_staff เดิม
- **คืนงาน/เปลี่ยนคนรับ/ข้าม**: ผู้รับคืนเองได้ (กลับรอรับงาน + แจ้งเตือนทีม), แอดมิน+ฝ่ายประสานงานเปลี่ยนคนรับและข้ามได้; ข้าม = ใบงานออกจากพูลโดยไม่มีผู้รับ พร้อมบันทึกเหตุผล
- **จบอัตโนมัติ**: ใบงานกราฟิกจบเมื่อ design_status ∈ {sent_email_cf, completed}; ใบงานหน้างานจบใน processEventReturn (ปิดอีเวนต์ → jobs onsite ของ lead นั้นเป็น done)
- **ทีม = แผนก (profiles.department)** ตั้งค่าราย category ใน job_settings: แผนก→ประเภทใบงาน และแผนกที่จอง/ย้ายกระเป๋าได้; UI ตั้งค่าอยู่ในหน้า /jobs/settings เดิม (admin เท่านั้น); มีค่า default ตามข้อ 26
- **แจ้งเตือน** ผ่านระบบ notifications เดิม: ใบงานใหม่ → สมาชิกแผนกของฝ่ายนั้น, รับ/คืน/ข้าม → แอดมิน+ฝ่ายประสานงาน; เรื่องเวลาไม่ยิงกระดิ่ง ใช้ป้ายบนหน้าจอ
- **โครงหน้า**: /jobs/tracking มี 3 แท็บ (ภาพรวม = ตารางเดิม, ใบงานกราฟิก, ใบงานหน้างาน) + ไทม์ไลน์เพิ่มเลนกระเป๋า
- **ความพร้อม 5 ข้อ**: ออกแบบ, จัดคน, จัดรถ, เวลาเริ่ม, กระเป๋า (จัดครบทุกใบที่จอง; งานไม่จองกระเป๋าเลย = ขาด "กระเป๋า" เฉพาะเมื่อใบงานหน้างานยังไม่ถูกข้าม — ตัดสินใจ: งานที่ไม่จองกระเป๋าเลยถือว่ายังขาด)
- **Backfill** script ครั้งเดียว (scripts/) สร้างใบงานให้ lead accepted ที่อีเวนต์ยังไม่ completed และ event_date ยังไม่ผ่าน
- **Migration ใหม่ทั้งหมดอยู่ใน supabase/migrations/** ตาม convention และเพิ่ม ActionType ใหม่ใน logger สำหรับทุก mutation ใหม่
- อัปเดตหน้า "มีอะไรใหม่" (whats-new) ใน commit เดียวกับการ ship ตามกติกา CLAUDE.md

## Testing Decisions

- โปรเจคไม่มี test runner — แนวทดสอบที่มีอยู่คือ **pure logic module + ไฟล์ self-check แบบ assert** (`tracking-logic.ts` + `tracking-logic.check.ts` รันด้วย tsx) — ใช้ seam เดิมนี้เป็นหลัก (seam เดียว): logic ใหม่ทั้งหมดที่ตัดสินใจได้แบบ pure (จัดกลุ่มใบงานเข้าแท็บ, กติกากระเป๋าชนรายวัน, ความพร้อม 5 ข้อ, เกณฑ์ใบงานจบ/ออกจากพูล, สิทธิ์ตามแผนก) เขียนเป็นฟังก์ชัน pure ใน tracking-logic แล้ว assert ใน check file
- ทดสอบพฤติกรรมภายนอกเท่านั้น (input → output ของฟังก์ชัน logic) ไม่ทดสอบ implementation detail ของ React component หรือ server action
- Server actions / UI verify ด้วย `npx tsc --noEmit` + `npm run build` + เปิดหน้าจริงตรวจด้วยตา (ไม่มี framework test สำหรับชั้นนี้ตาม convention โปรเจค)

## Out of Scope

- การแก้ flow เช็คกระเป๋า "ขาคืน" (processEventReturn) นอกเหนือจากการปิดใบงานหน้างานอัตโนมัติ
- การย้าย design_status / required_roles จาก crm_leads ไปตาราง jobs
- Mobile app / LINE notification — แจ้งเตือนผ่านกระดิ่งในระบบเท่านั้น
- การเปลี่ยนสิทธิ์ระดับ module (MODULE_ROUTES / proxy.ts) — พูลยังอยู่ใต้ module jobs เดิม
- รายงาน/สถิติการรับงาน (เช่น ใครรับกี่งานต่อเดือน)
