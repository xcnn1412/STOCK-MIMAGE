# เปิดใบงานกราฟิกจากการ์ด CRM (manual open)

## Problem Statement

ใบงานกราฟิกถูกสร้างอัตโนมัติทันทีที่การ์ด CRM เป็น "ตอบรับ" ทำให้จุดกำเนิดของใบงานกราฟิกต่างจากอีเวนต์ (ที่ต้องกดเปิดจากการ์ด CRM) — flow ไม่สมมาตร และงานที่ลูกค้าออกแบบเองได้ใบงานกราฟิกที่ไม่จำเป็นมา ต้องตามไปกด "ข้าม" ทีหลัง

## Solution

ใบงานกราฟิกเกิดจากการ**กดเปิดเองบนการ์ด CRM** (ปุ่ม "เปิดใบงานกราฟิก" เมื่องานตอบรับแล้วและยังไม่มีใบงานกราฟิก) เปิดแล้วเข้าพูลสถานะ "รอรับงาน" + แจ้งเตือนฝ่ายออกแบบ — ใบงานหน้างานยังเกิดอัตโนมัติตอนตอบรับเหมือนเดิม (แท็บเห็นเฉพาะแอดมิน ไม่รบกวนใคร) งานที่ยังไม่เปิดใบงานกราฟิกแสดงป้าย "ยังไม่เปิดใบงาน" สีเตือนในคอลัมน์ออกแบบของตารางภาพรวม เพื่อกันงานเงียบหายเพราะลืมเปิด

## User Stories

1. As a แอดมิน, I want ปุ่ม "เปิดใบงานกราฟิก" บนการ์ด CRM ที่ตอบรับแล้ว, so that ผมคุมจังหวะได้ว่างานไหนต้องออกแบบ งานไหนลูกค้าออกแบบเอง
2. As a แอดมิน, I want ปุ่มหายไปเมื่องานมีใบงานกราฟิกแล้ว, so that ไม่เปิดซ้ำ
3. As a สมาชิกฝ่ายออกแบบ, I want กระดิ่งแจ้งเตือนตอนใบงานกราฟิกถูกเปิด, so that รู้ทันทีว่ามีงานใหม่ให้กดรับ
4. As a ฝ่ายประสานงาน, I want งานที่ยังไม่เปิดใบงานกราฟิกขึ้นป้าย "ยังไม่เปิดใบงาน" สีเตือนในคอลัมน์ออกแบบ, so that เห็นทุกครั้งที่เปิดภาพรวมว่างานไหนอาจถูกลืม
5. As a ระบบ, I want การตอบรับสร้างเฉพาะใบงานหน้างานอัตโนมัติ, so that flow ของกราฟิกกับอีเวนต์สมมาตรกัน (เกิดจากการกดที่การ์ด CRM ทั้งคู่)
6. As a แอดมิน, I want ตัวกันสร้างซ้ำแยกรายประเภทใบงาน, so that งานที่มีใบงานหน้างานแล้วยังเปิดใบงานกราฟิกทีหลังได้
7. As a ผู้ใช้, I want ทุกการเปิดใบงานถูกบันทึกใน activity log, so that ตรวจย้อนหลังได้ว่าใครเปิดเมื่อไหร่
8. As a ผู้ใช้เดิม, I want งานที่มีใบงานกราฟิกอยู่แล้ว (จาก auto/backfill เดิม) ทำงานเหมือนเดิมทุกอย่าง, so that ไม่มีอะไรพังจากการเปลี่ยน flow

## Implementation Decisions

- Hook ตอนตอบรับเปลี่ยนจาก "สร้าง 2 ใบ" เป็น "สร้างเฉพาะใบงานหน้างาน" — ใบงานกราฟิกเกิดจาก action ใหม่ที่เรียกจากปุ่มบนหน้ารายละเอียด lead เท่านั้น
- ตัวกันซ้ำเปลี่ยนจาก "lead นี้มี jobs แถวใดๆ" เป็น "lead นี้มี jobs ของ job_type นั้น" — ทั้งฝั่ง auto (onsite) และฝั่ง manual (graphic)
- ปุ่มเปิดใบงานกราฟิก: เห็นเมื่อ lead.status = accepted และยังไม่มีใบงานกราฟิก; ใครกดได้ = ตาม flow เดิมของปุ่มส่งต่องาน (ไม่เพิ่มชั้นสิทธิ์ใหม่)
- คอลัมน์ออกแบบในภาพรวม: ไม่มีใบงานกราฟิก = ป้าย "ยังไม่เปิดใบงาน" (โทนเตือน) แทน dropdown — งานเก่าก่อนยุคพูลที่ไม่มีใบงานถูกปฏิบัติแบบเดียวกัน (เปิดจากการ์ด CRM ได้เช่นกัน)
- สถานะป้ายในคอลัมน์ออกแบบไล่เป็นขั้น: ยังไม่เปิดใบงาน → รอรับงาน (ปุ่มรับ) → ตัวแก้สถานะออกแบบ
- แจ้งเตือนใช้เส้นทางเดิม (job_pool_new ถึงแผนกฝ่ายกราฟิกตามการตั้งค่า) — ยิงตอนเปิดใบงาน
- ActionType ใหม่สำหรับการเปิด manual; ปุ่ม "ส่งต่องาน" เดิมบนหน้า lead ปรับให้สอดคล้อง (ไม่สร้างกราฟิกซ้ำถ้ามีแล้ว)
- ไม่แตะ schema

## Testing Decisions

- Seam เดิมตัวเดียว: pure logic ใน tracking-logic + assert ใน tracking-logic.check.ts — เพิ่มฟังก์ชันตัดสินสถานะช่องออกแบบ (ยังไม่เปิด/รอรับ/แก้ได้) จาก job ที่ส่งเข้า และ assert ครบทุกกิ่ง
- Server actions / UI ตรวจด้วย `npx tsc --noEmit` + `npm run build` + เปิดหน้าจริง ตาม convention โปรเจค

## Out of Scope

- เปลี่ยน flow ใบงานหน้างาน (ยังอัตโนมัติ)
- เปลี่ยนระบบหน้าที่เตรียมงาน / กระเป๋า / รถ
- ปุ่มเปิดใบงานจากที่อื่นนอกการ์ด CRM

## Further Notes

- ย้อนการตัดสินใจ Q3 (auto ทั้งคู่) ของ spec jobs-pool เดิม — ผู้ใช้ยืนยันแล้วว่ารับ trade-off (เพิ่ม 1 คลิก/งาน แลกกับคุมจังหวะได้และ flow สมมาตรกับอีเวนต์)
- backfill script เดิมไม่ต้องแก้ (สร้างให้เฉพาะงานเก่าที่ยังไม่จบ ซึ่งควรมีใบงานครบอยู่แล้ว)
