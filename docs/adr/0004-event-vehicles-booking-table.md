# จัดรถผูกกับอีเวนต์ผ่านตาราง event_vehicles แทน key ใน tracking_checklist

"จัดรถ" เดิมเก็บเป็น key (`car_triton` / `car_champ`) ใน `crm_leads.tracking_checklist` ซึ่งผูกกับ **งาน** ไม่ใช่ **อีเวนต์** ต่างจากคน (`event_staff`) และกระเป๋า (`event_kits`) ที่ผูกอีเวนต์ไปแล้ว — งานที่มีหลายอีเวนต์จึงบอกไม่ได้ว่ารถไปกับใบไหน เราจึงเพิ่มตารางจอง `event_vehicles` (event_id, vehicle_key, unique(event_id, vehicle_key)) และให้มันเป็น source of truth ของการจัดรถ · `assignLeadVehicle` หาอีเวนต์ปลายทางด้วย `resolveLeadEvent(pickExisting)` เส้นทางเดียวกับจองกระเป๋า (งานที่ยังไม่มีอีเวนต์ ระบบเปิดให้อัตโนมัติ) ลบการจองรถเก่าของทุกอีเวนต์ของงานนั้น แล้วใส่คันใหม่ให้ใบที่เลือก

`crm_leads.tracking_checklist` **คงไว้เป็น cache** ที่ action เดียวกันนี้ sync ให้ทุกครั้ง (เหลือ key รถคันที่เลือกคันเดียว รายการอื่นไม่แตะ) — read path เดิมทั้งหมด (`vehicleOf`, เกณฑ์ความพร้อมข้อ "จัดรถ", เลนรถบนไทม์ไลน์, การชน, สรุปหน้าที่เตรียมงาน) ยังอ่านที่เดิมโดยไม่ต้องแก้ เป็น expand–contract: ขั้น contract (ให้ read path อ่าน `event_vehicles` ตรงๆ) ค่อยทำทีหลังเมื่อมีคนอยากจัดรถคนละคันต่ออีเวนต์จริง

กติกาชนของรถ**ไม่เปลี่ยน** — ยังตัดสินด้วย "เวลาทับกัน" (มีต่อคิวได้เมื่อวันเดียวกันแต่เวลาไม่ทับ) ต่างจากกระเป๋าที่ถือว่าจองสองอีเวนต์วันเดียวกัน = ชนทันทีโดยไม่ดูเวลา จึงไม่มี constraint เรื่องการชนในฐานข้อมูล ตัดสินในโค้ด (`tracking-logic.ts`) เหมือนเดิม
