# จองกระเป๋าผ่านตาราง event_kits แทน kits.event_id เดี่ยว

`kits.event_id` ผูกกระเป๋าได้ทีละหนึ่งอีเวนต์ ทำให้วางแผนล่วงหน้าไม่ได้ (จองกระเป๋าให้งานสัปดาห์หน้าไม่ได้ถ้าวันนี้ยังอยู่กับอีกงาน) และเลนกระเป๋าบนไทม์ไลน์จะเห็นได้ทีละงานเดียว เราจึงเพิ่มตารางจอง `event_kits` (event_id, kit_id, packed_at, packed_by) — กระเป๋าใบเดียวจองหลายอีเวนต์คนละวันได้, กติกาชน = จองสองอีเวนต์วันเดียวกัน (เข้มกว่าคน/รถ: ไม่ดูเวลา ไม่มีต่อคิว), สถานะจัดกระเป๋าเก็บต่อการจองจึงรีเซ็ตเองเมื่อย้ายอีเวนต์ `kits.event_id` เดิมคงไว้เพื่อ backward compat กับ flow เช็ค/คืนกระเป๋าเดิม โดยถือว่า event_kits เป็น source of truth ของการจอง

## แก้ไข (v1.29.0, 2026-10-03)

- **ทุกทางใช้ event_kits แล้ว:** หน้าสร้าง/แก้ไขอีเวนต์, หน้า Kits ของอีเวนต์, หน้าคืนกระเป๋า และหน้าเช็คของ อ่าน/เขียนการจองที่ `event_kits` ทั้งหมด (backfill การผูกเดิมด้วย `20261003_event_kits_backfill.sql`)
- **`kits.event_id` = ตัวชี้ที่คำนวณได้:** "ตอนนี้กระเป๋าอยู่กับงานไหน" = การจองของอีเวนต์ที่ยังไม่ปิดที่วัน/เวลาเร็วที่สุด (`pickKitPointer`, `recomputeKitPointers` ใน `lib/kit-bookings.ts`) คำนวณใหม่ทุกครั้งที่จอง/ยกเลิก/แก้อีเวนต์/ปิดงาน — ปิดงานแล้วตัวชี้ย้ายไปงานถัดไปเอง ไม่ต้องเขียนตรงอีก
- **กติกาชนเปลี่ยน:** จากเดิม "วันเดียวกัน = ชน ไม่ดูเวลา และบล็อก" เป็นดูเวลาแบบเดียวกับคน/รถ (`kitBookingClashes`): เวลาทับ = ชน, เวลาไม่ทับ = ต่อคิว, ขาดเวลา = เช็คเวลาไม่ได้ — **ทุกกรณีแค่เตือน ไม่บล็อก** ทั้งฟอร์มอีเวนต์และพูลงาน ของจริงกันด้วยการนำออกได้เฉพาะอุปกรณ์สถานะ "ว่าง" (งานแรกยังไม่คืน งานถัดไปนำออกไม่ได้)
- **"จัดครบ" (`packed_at`)** = อุปกรณ์ทุกชิ้นในกระเป๋าถูกนำออกให้อีเวนต์นั้นแล้ว — server คิดให้ตอนนำออก/รับคืน แทนการติ๊กครบ
